# Docs — what is where

Read `state.md` first. Everything else is reference.

| File | What it is | Kept current? |
|---|---|---|
| `state.md` | Where things stand, what is next, gotchas, dated Done log | Yes, every milestone |
| `go-live.md` | The four-stage plan to launch; ticked as items are done | Yes |
| `ARCHITECTURE.md` | How the app works: layout, data, API, who may call what | Yes |
| `payments.md` | Easebuzz gateway, fallbacks, switch-on steps | Yes |
| `testing.md` | The test layers and what each proves | Yes |
| `design-scale.md` | Sizes, spacing, motion values new screens pick from | Yes |
| `audit.md` | System audit: open issues and fixed ones (launch blockers in section A) | Ticked as fixed |
| `ui-audit.md` | UI and customer-flow audit | Ticked as fixed |
| `accuracy-audit.md` | Money, order numbers and reports audit | Ticked as fixed |
| `menu-audit.md` | Owner-menu audit across every screen (all fixed) | Closed |
| `feature-research.md` | What other restaurant systems do that we don't, ranked | Snapshot, 2026-11-15 |
| `history/` | Plans written before the build. Not how the app works today. | No |

Rules: one fact lives in one file; when something stops being true, edit it in place instead of adding a caveat; history goes in the Done log of `state.md`.
